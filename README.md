# Сессионный проект — вариант 4

**Лукьянчиков Валерий Геннадьевич**

Тема: помещения и стеллажи. Программа написана на Python и работает с PostgreSQL через библиотеку psycopg2.

Таблицы `rooms` и `racks` взяты из моего домашнего задания по модулю 1. Другие таблицы из домашнего задания в этом проекте не используются.

## Что умеет программа

- Показать список помещений, добавить, изменить и удалить помещение.
- Открыть стеллажи выбранного помещения, добавить и удалить стеллаж.
- Удалять помещение со связанными стеллажами только после подтверждения.
- Проверять ввод: числа, длину названия, температуру, влажность, размеры стеллажей.
- Показывать ошибки понятным сообщением, не выполняя SQL с подставленным пользовательским текстом.

В меню пользователь выбирает номер строки на экране. Поля `id` и `room_id` используются только внутри программы; вводить их не нужно. SQL-запросы используют параметры `%s`, имена таблиц оформляются через `psycopg2.sql.Identifier`.

## Запуск на Windows

1. Установите PostgreSQL, Python и VS Code.
2. Создайте базу `warehouse_session_v4` в pgAdmin.
3. В Query Tool, подключённом к **warehouse_session_v4**, выполните `sql/01_schema.sql`. Он создаст схему `session_v4` и две таблицы: `rooms` и `racks`.
4. Для примеров можно один раз выполнить `sql/02_demo_data.sql`.
5. Откройте каталог проекта в VS Code. В терминале выполните:

```powershell
python -m pip install -r requirements.txt
Copy-Item config.example.yaml config.yaml
```

Если `config.yaml` уже есть, повторно копировать его не надо. Откройте `config.yaml` и заполните настройки **своего** PostgreSQL:

```yaml
dbname: warehouse_session_v4
user: postgres
password: "ЗДЕСЬ_СВОЙ_ПАРОЛЬ"
host: localhost
port: 5432
schema: session_v4
```

Замените пример пароля на настоящий. Сохраните файл. Запуск:

```powershell
python main.py
```

В главном меню нажмите `1`, затем выберите действие. Если программа не может подключиться к серверу, проверьте `config.yaml`, работающий сервер PostgreSQL и пароль.

## Проверка перед сдачей

В терминале выполните:

```powershell
python -m unittest discover -s tests -v
```

Проверки в `tests` не создают данные в базе: они проверяют валидацию и работу меню с имитацией таблиц.

Чтобы проверить базу на своём компьютере:

1. Посмотрите помещения и их стеллажи (уже проверено при настройке).
2. Добавьте новое **тестовое** помещение и проверьте, что оно появилось.
3. Измените его объём.
4. Добавьте два стеллажа в это помещение и проверьте отображение.
5. Попробуйте добавить стеллаж с тем же номером в то же помещение: должна появиться понятная ошибка.
6. Попробуйте отрицательный объём, нулевое количество мест, влажность больше 100 или неверный диапазон температур. Программа должна попросить исправить ввод.
7. Удалите один из тестовых стеллажей.
8. Удалите тестовое помещение со связанным стеллажом: программа должна запросить подтверждение. Не удаляйте рабочие данные.

**Ограничение проверки:** автоматические тесты без PostgreSQL не заменяют тестирование всех операций на настоящем сервере.

## Что лежит в проекте

- `main.py` — меню и ввод пользователя. В начале указан студент и условие варианта.
- `validation.py` — проверка вводимых данных.
- `project_config.py`, `dbconnection.py` — настройки и подключение.
- `dbtable.py` — общие методы работы с БД.
- `tables/rooms_table.py`, `tables/racks_table.py` — запросы для двух таблиц.
- `sql/01_schema.sql` — создание таблиц, `sql/02_demo_data.sql` — тестовые данные.
- `tests/` — тесты.
